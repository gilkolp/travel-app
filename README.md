# הטיולים שלי — אפליקציית טיולים (PWA)

אפליקציית טיולים אישית בעברית, שעובדת בדפדפן ומתקינה על מסך הבית של הטלפון כמו אפליקציה רגילה.
קבצים סטטיים בלבד — בלי שרת, בלי שלב בנייה (build). כל הנתונים נשמרים **מקומית על המכשיר** של כל משתמש (IndexedDB): טיולים, חלקי טיול, יומן, תמונות ומסמכים.

## מה האפליקציה עושה

- **שעון כפול בראש כל מסך** — שעון ישראל + שעון החלק הפעיל בטיול, מתקתקים.
- **חלקי טיול (Stops)** — טיול מתחלק לערים, לכל חלק תאריכי הגעה ועזיבה משלו. אם עוד לא יודעים את החלוקה, מספיק חלק כללי אחד על שם המדינה.
- **החלק הפעיל** — בורר בראש המסך (ידני או אוטומטי לפי התאריך של היום). השעון, מזג האוויר, האטרקציות, הכשרות, חב״ד והלינה — כולם מכוונים לפי החלק הפעיל.
- **מזג אוויר** — תחזית יומית מ־Open-Meteo לפי טווח התאריכים של החלק הפעיל (או לשבוע הקרוב).
- **אטרקציות / אוכל כשר / בית חב״ד** — חיפוש סביב החלק הפעיל או סביב המיקום הנוכחי של המכשיר, מתוך OpenStreetMap (Overpass API), עם מרחק וקישור ניווט ל־Google Maps.
- **לינה** — קישורי חיפוש ל־Booking.com ול־Airbnb לפי היעד והתאריכים (ההזמנה עצמה באתר החיצוני).
- **יומן טיול** — רשומות עם תמונה וטקסט לאורך הטיול, ומצב **מצגת סיום** שמריץ את הרשומות כמצגת עם כיתובים.
- **מסמכים** — העלאת ביטוח, אישורי הזמנות וכרטיסים, מסודרים לפי קטגוריות, לצפייה והורדה.
- **שותפים** — מוסיפים את מי שטס יחד (שותף מעדכן / עוקב), בוחרים "מי מעדכן" למעלה, והשם נשמר ליד כל רשומה, חלק ומסמך.
- **שיתוף** — ייצוא עמוד HTML עצמאי אחד (צפייה בלבד: מסלול, חלק פעיל ויומן, בלי קבצי המסמכים) שמורידים ושולחים למשפחה ולחברים.

יומן, מצגת ומסמכים הם כלליים לכל הטיול; כל השאר מכוון לפי החלק הפעיל.

## מבנה הפרויקט

```
travel-app/
├── index.html            # מעטפת האפליקציה וכל המסכים
├── style.css             # עיצוב (מותאם מובייל, RTL)
├── manifest.webmanifest  # הגדרות PWA להתקנה על מסך הבית
├── sw.js                 # Service Worker — מעטפת אופליין
├── icon.svg              # אייקון האפליקציה
└── js/
    ├── db.js             # שכבת נתונים — IndexedDB מקומי
    ├── api.js            # Open-Meteo (מזג אוויר/חיפוש יעד) + Overpass (מקומות)
    └── app.js            # לוגיקת האפליקציה והמסכים
```

## איך מעלים ל־GitHub Pages

1. פתח חשבון חינמי ב־[github.com](https://github.com) אם אין לך.
2. צור מאגר (Repository) חדש, למשל בשם `travel-app`, ובחר Public.
3. העלה את כל קבצי התיקייה הזו למאגר (Add file → Upload files) — חשוב לשמור על מבנה התיקיות, כולל תיקיית `js`.
   - לחלופין, עם Git מותקן: `git clone` למאגר, העתק את הקבצים פנימה, ואז `git add . && git commit -m "travel app" && git push`.
4. במאגר: Settings → Pages → תחת "Build and deployment" בחר Source: **Deploy from a branch**, Branch: **main**, תיקייה **/ (root)**, ושמור.
5. אחרי כדקה יופיע קישור האתר, בפורמט: `https://<username>.github.io/travel-app/`
6. פתח את הקישור בטלפון → תפריט הדפדפן → "הוסף למסך הבית" — האפליקציה תותקן עם אייקון משלה.

כל מי שיקבל את הקישור יוכל להתקין ולהשתמש — הנתונים של כל אחד נשמרים על המכשיר שלו בלבד ולא מתערבבים.

## שירותים חיצוניים (חינמיים, בלי מפתח)

- **Open-Meteo** — חיפוש יעד (Geocoding) ותחזית מזג אוויר. לא דורש הרשמה.
- **Overpass API / OpenStreetMap** — אטרקציות, מסעדות כשרות (לפי תגיות `diet:kosher` / `kosher` ב־OSM) ובתי חב״ד. הכיסוי תלוי במידע שהוזן למפה באותו אזור.
- **Google Maps** — קישורי ניווט בלבד.

## בעתיד: שמירה בענן (Firebase / Supabase)

כרגע הכל נשמר מקומית על המכשיר. אם תרצה שהנתונים יגובו בענן ויסתנכרנו בין מכשירים, אפשר לחבר אחד משני שירותים עם שכבה חינמית נדיבה:

- **Firebase** (Google) — Firestore לנתונים + Storage לקבצים ותמונות.
  1. ב־[console.firebase.google.com](https://console.firebase.google.com) צור פרויקט.
  2. Build → Firestore Database → Create database; ו־Build → Storage → Get started.
  3. Project settings → "Your apps" → Web — קבל את אובייקט `firebaseConfig`.
- **Supabase** — Postgres + Storage, קוד פתוח.
  1. ב־[supabase.com](https://supabase.com) צור פרויקט.
  2. Project Settings → API — קבל את `Project URL` ואת `anon key`.

**איפה להדביק את ההגדרות:** צור קובץ חדש בשם `js/cloud-config.js` בתיקיית `js`, עם התוכן הבא (לפי השירות שתבחר), והוסף אותו כסקריפט ב־`index.html` לפני `js/app.js`:

```js
// js/cloud-config.js — למלא רק אם מחברים ענן
window.CLOUD = {
  provider: 'firebase', // או 'supabase'
  firebase: {
    apiKey: '...',
    authDomain: '...',
    projectId: '...',
    storageBucket: '...',
    appId: '...'
  },
  supabase: {
    url: 'https://xxxx.supabase.co',
    anonKey: '...'
  }
};
```

הערה: חיבור ענן בפועל דורש גם שכבת סנכרון (העלאת הנתונים מ־IndexedDB לענן והתחברות משתמשים) — זהו פיתוח נוסף מעבר לגרסה הנוכחית, שבה `js/db.js` הוא מקור האמת היחיד והמקומי.

## פרטיות
